# QuickMind Stage 1／v1 產品規格

狀態：ready-for-agent  
範圍：第一階段核心流程  
正常使用情境：50 個節點以下的單一本機心智圖

## Problem Statement

個人桌面使用者需要一個開啟即能使用的心智圖工具，把尚未成形的想法快速拆解成可回看的階層結構。使用者不希望為了整理私人想法而登入、上傳或依賴雲端服務，也不希望在瀏覽器重新開啟後失去尚未手動匯出的內容。

目前的初始規格把大量尚未驗證的技術方案、極端規模目標與後續能力混在同一份文件中，反而沒有先清楚定義第一階段的可交付使用情境、資料安全邊界與驗收方式。本規格將第一階段收斂為可在桌面瀏覽器中完成的本機單一文件核心流程。

## Solution

QuickMind Stage 1 提供一個部署在 GitHub Project Pages 的純靜態桌面瀏覽器應用程式。使用者可以在第一次成功載入後離線建立、編輯、保存與恢復一份本機心智圖，並透過階層節點、拖曳、展開／收合與 Undo／Redo 快速整理想法。

第一階段以 50 個節點以下作為正常使用與驗收情境。完整文件資料留在瀏覽器本機，不提供登入、後端 API、遙測、雲端同步或團隊協作。使用者可明確匯出與重新匯入版本化的 QuickMind 原生 .quickmind 檔案，作為完整 round-trip 格式。

Stage 1 的交付流程也必須可重複驗證：本地與 GitHub Actions 共用 Docker Compose 執行入口，開發、型別檢查、domain／unit tests、Chromium E2E 與 build 都在 Docker 內執行；Pull Request 必須通過全部檢查，`main` 分支只有在全部檢查通過後才發布到 GitHub Project Pages。正式發布與本地 preview 都不需要 Nginx。

## User Stories

1. As a 個人桌面使用者, I want to 在桌面瀏覽器直接開啟 QuickMind, so that 我可以立即開始整理想法而不需要註冊帳號。
2. As a 個人桌面使用者, I want to 第一次開啟時看到一份含有「未命名心智圖」根節點的新文件, so that 我知道可以從哪裡開始輸入。
3. As a 個人桌面使用者, I want to 重新開啟時自動恢復瀏覽器本機的工作副本, so that 尚未匯出的內容不會因為關閉分頁而消失。
4. As a 個人桌面使用者, I want to 重新命名根節點, so that 心智圖有清楚的主題名稱。
5. As a 個人桌面使用者, I want to 新增一個子節點, so that 我可以把目前想法向下拆解。
6. As a 個人桌面使用者, I want to 新增一個同層節點, so that 我可以在同一層補充另一個平行想法。
7. As a 個人桌面使用者, I want to 重新命名任何節點, so that 階層中的每個想法都能用簡短文字表達。
8. As a 個人桌面使用者, I want to 取消正在進行的重新命名, so that 我可以保留原本的標題。
9. As a 個人桌面使用者, I want to 送出空白的新節點時自動取消新增, so that 文件中不會留下沒有意義的空白節點。
10. As a 使用 CJK 輸入法的使用者, I want to 在組字期間輸入 Enter 或其他快捷鍵時由輸入法優先處理, so that 中文輸入不會被誤提交或誤觸發節點操作。
11. As a 個人桌面使用者, I want to 使用 Delete 刪除目前選取的非根節點及其子樹, so that 我可以一次移除不需要的分支。
12. As a 個人桌面使用者, I want to 透過一次 Undo 還原被刪除的整棵子樹, so that 誤刪時可以快速復原。
13. As a 個人桌面使用者, I want to 不能刪除根節點, so that 每份文件永遠維持可用的單一入口。
14. As a 個人桌面使用者, I want to 把節點拖到目標的上方或下方, so that 我可以調整同層節點順序。
15. As a 個人桌面使用者, I want to 把節點拖到目標的中央, so that 我可以把它移動成目標的子節點。
16. As a 個人桌面使用者, I want to 系統拒絕把節點拖進自己的後代, so that 階層不會形成循環或破壞樹狀結構。
17. As a 個人桌面使用者, I want to 移動節點後焦點仍留在被移動的節點, so that 我可以繼續操作剛剛整理的位置。
18. As a 個人桌面使用者, I want to 展開或收合有子節點的節點, so that 我可以在完整內容與簡潔視圖之間切換。
19. As a 個人桌面使用者, I want to 收合狀態只隱藏後代而不刪除內容, so that 我可以安全地暫時縮小視圖。
20. As a 個人桌面使用者, I want to 使用方向鍵在目前可見的節點間移動, so that 我可以不依賴滑鼠瀏覽階層。
21. As a 個人桌面使用者, I want to 使用 Enter 與 Tab 快捷鍵建立同層或子節點, so that 我可以連續輸入而不必反覆切換滑鼠與鍵盤。
22. As a 個人桌面使用者, I want to 使用雙擊或 F2 進入標題編輯, so that 我可以快速修改現有節點。
23. As a 個人桌面使用者, I want to 點擊空白畫布清除選取但不建立內容, so that 我可以重新整理視線而不產生意外變更。
24. As a 個人桌面使用者, I want to 使用右鍵選單執行既有節點操作, so that 我可以依照自己的操作習慣使用滑鼠。
25. As a 個人桌面使用者, I want to 右鍵選單與鍵盤操作使用相同的行為, so that 不同輸入方式不會產生不一致的文件結果。
26. As a 個人桌面使用者, I want to 使用 Undo 還原最近一次文件變更, so that 我可以安全地嘗試不同的階層整理方式。
27. As a 個人桌面使用者, I want to 使用 Redo 恢復被 Undo 的變更, so that 我可以在比較結果後回到較新的狀態。
28. As a 個人桌面使用者, I want to 在畫面上看到 Undo／Redo 按鈕與停用狀態, so that 我不需要記住快捷鍵也能操作歷史。
29. As a 個人桌面使用者, I want to 連續編輯一個標題只形成一筆歷史, so that 一次文字修改可以一次完整還原。
30. As a 個人桌面使用者, I want to 在 Undo 後做新變更時清除不再適用的 Redo 分支, so that 歷史不會把文件帶到矛盾狀態。
31. As a 個人桌面使用者, I want to 每一個文件操作都維持樹狀不變量, so that 文件永遠只有一個根，且每個非根節點只有一個父節點。
32. As a 個人桌面使用者, I want to 可以使用相同的節點標題, so that 我不需要為了避免重複而改變自然的想法表達。
33. As a 個人桌面使用者, I want to 節點擁有穩定且不依賴標題的識別, so that 移動、匯出與重新匯入不會混淆同名節點。
34. As a 個人桌面使用者, I want to 節點標題限制在可理解的可見字元上限內, so that 畫面與原生檔案不會被無限制文字破壞。
35. As a 個人桌面使用者, I want to 看到根節點位於左側、子節點向右展開的自動布局, so that 階層關係能被快速理解。
36. As a 個人桌面使用者, I want to 同層順序在畫面、工作副本與原生檔案中一致, so that 我調整的順序不會在保存或恢復後改變。
37. As a 個人桌面使用者, I want to 視圖平移、縮放與目前選取不污染文件內容, so that 瀏覽畫布不會產生不必要的歷史或文件變更。
38. As a 個人桌面使用者, I want to 重新開啟或匯入時從穩定的初始畫布狀態開始, so that 不會被上次的鏡頭位置或選取狀態干擾。
39. As a 個人桌面使用者, I want to 文件變更自動保存到本機, so that 我不必為每個小變更手動保存。
40. As a 個人桌面使用者, I want to 看見「已保存到本機」與「尚未匯出」等不同狀態, so that 我能分辨瀏覽器保存與原生檔案備份的差異。
41. As a 個人桌面使用者, I want to 本機保存失敗時保留畫面中的內容並看到警告, so that 短暫的儲存問題不會直接造成資料遺失。
42. As a 個人桌面使用者, I want to 在本機保存失敗時重試或匯出救援檔案, so that 我仍有可操作的資料救援路徑。
43. As a 個人桌面使用者, I want to 保存失敗時不能靜默覆蓋目前工作副本, so that 我不會在錯誤狀態下遺失正在編輯的內容。
44. As a 個人桌面使用者, I want to 清除唯一的本機文件前收到明確確認, so that 危險操作不會因誤觸而刪除工作內容。
45. As a 個人桌面使用者, I want to 匯出 QuickMind 原生檔案, so that 我可以保存、備份或交給另一個 QuickMind 工作階段重新開啟。
46. As a 個人桌面使用者, I want to 匯出的 .quickmind 檔案保留文件 ID、節點 ID、階層順序、標題、時間與收合狀態, so that 同版重新匯入時能得到一致的文件。
47. As a 個人桌面使用者, I want to 匯入有效的 .quickmind 檔案取代目前文件, so that 我可以繼續編輯外部保存的工作。
48. As a 個人桌面使用者, I want to 匯入前在有未匯出變更時被提醒, so that 我不會無意覆蓋目前工作。
49. As a 個人桌面使用者, I want to 匯入後用一次 Undo 回到匯入前的完整文件, so that 文件替換仍然可逆。
50. As a 個人桌面使用者, I want to 無效或不支援版本的原生檔案被拒絕且不影響目前文件, so that 損毀或未知格式不會污染工作區。
51. As a 個人桌面使用者, I want to 匯入失敗時看到可理解的錯誤與必要的技術位置, so that 我可以判斷是檔案問題還是操作問題。
52. As a 個人桌面使用者, I want to 相同文件重複匯入時不產生多餘歷史或保存, so that 無實質變更的操作不會污染文件狀態。
53. As a 個人桌面使用者, I want to 超過文件大小或節點上限的操作被完整拒絕, so that 系統不會靜默截斷或刪除資料。
54. As a 個人桌面使用者, I want to 已成功載入後即使網路中斷仍可繼續核心操作, so that 我可以在沒有網路的環境整理想法。
55. As a 個人桌面使用者, I want to 第一次從未載入且離線時看到需要先連線的說明, so that 我能理解瀏覽器尚未有可用的應用程式快取。
56. As a 個人桌面使用者, I want to 網路恢復時不會自動上傳本機文件, so that local-first 與隱私承諾不會被破壞。
57. As a 鍵盤使用者, I want to 所有核心操作都有清楚可見焦點與可理解名稱, so that 我不需要依賴滑鼠或顏色才能使用。
58. As a 使用輔助技術的使用者, I want to 核心控制項使用原生語意與基本可讀對比, so that v1 的基本可用性不依賴特定自訂 ARIA 架構。
59. As a 個人桌面使用者, I want to 在支援的桌面 Chrome 或 Edge 版本中使用相同核心行為, so that 我知道正式支援的瀏覽器範圍。
60. As a 專案維護者, I want to 用 Docker 重現建置, so that 本機與 CI 不會因建置環境差異產生不可解釋的結果。
61. As a 專案維護者, I want to Pull Request 自動執行建置與核心測試, so that 未驗證的變更不會直接進入主分支。
62. As a 專案維護者, I want to 只有通過全部檢查的 main 變更才發布到 GitHub Pages, so that 正式站保持可驗證且可使用的版本。
63. As a 專案維護者, I want to 以核心行為與資料安全而不是技術框架數量判斷完成度, so that Stage 1 能快速交付並保留後續演進空間。

## Implementation Decisions

- **產品邊界**：Stage 1 面向個人桌面使用者，在桌面 Chrome 與 Edge 最新兩個主要版本中使用。正式發布為 GitHub Project Pages 純靜態網站；不提供後端 API、登入、遙測、雲端同步、團隊協作或行動瀏覽器承諾。
- **單一文件工作區**：同一時間只處理一份本機心智圖，不提供多草稿頁籤、多文件工作階段或文件合併。啟動時優先恢復本機工作副本，沒有工作副本才建立新的「未命名心智圖」。
- **資料模型**：文件是一棵嚴格階層樹，必須且只能有一個根節點；每個非根節點恰有一個父節點；節點的 children 順序就是同層顯示與保存順序。v1 不包含跨連結、分組外框、多父節點、自由畫布、多選或批次操作。
- **節點內容**：節點只有單行純文字標題；根節點與一般節點不可提交空白；提交時移除前後空白、保留中間空白；標題最多 200 個使用者可見字元；同層允許同名節點。Markdown 備註、圖片附件與個別節點樣式不屬於 v1。
- **識別與時間**：文件與節點使用 UUID v4 字串；新文件與新節點建立時取得 ID，取消新增不重用 ID，原生檔案 round-trip 保留既有 ID。原生文件 metadata 只包含 id、schemaVersion、createdAt、updatedAt；時間使用 UTC ISO 8601 字串。
- **文件操作**：支援新增子節點、新增同層節點、重新命名、刪除子樹、拖曳移動、展開／收合與 Undo／Redo。刪除非根節點會刪除整棵子樹，單次 Undo 完整還原；根節點不可刪除。拖曳上方／下方改變同層位置，拖曳中央成為目標的最後一個子節點；根節點不可拖曳，也不可拖入自己的後代。
- **編輯與焦點**：新增節點後立即進入編輯；Enter 提交，Esc 取消；CJK 組字期間不攔截輸入法按鍵。單擊選取，雙擊或 F2 編輯，空白畫布清除選取。刪除後焦點依序回到前一個同層節點、下一個同層節點或父節點；拖曳後焦點留在被移動節點。
- **鍵盤與情境選單**：非編輯狀態下 Enter 建立同層、Tab 建立子節點、Delete 刪除非根選取、Space 切換展開／收合；方向鍵只導覽可見節點。Undo／Redo 使用 Ctrl／Cmd+Z、Ctrl／Cmd+Shift+Z，Windows／Linux 另支援 Ctrl+Y。提供可見且使用原生語意的 Undo／Redo 按鈕與節點情境選單。
- **歷史**：所有文件內容或結構變更，包括展開／收合、匯入取代與刪除子樹，都進入文件歷史；每個使用者動作形成一筆歷史，標題編輯在提交時形成一筆。v1 最多保留最近 100 個文件操作；Undo 後的新變更清除 Redo 分支；Undo／Redo 恢復後立即保存完整工作狀態，但不改寫被恢復狀態原有的時間或匯出狀態。
- **布局與視圖**：節點位置由階層與展開狀態計算，不寫入原生文件，也不支援自由定位。布局方向固定為根節點在左、子節點向右、同層由上至下。平移、縮放與目前選取是視圖狀態，不進文件歷史、不保存；重新開啟或匯入從 100% 縮放、根節點置中、無選取開始。
- **本機保存**：新文件建立即保存到瀏覽器本機工作副本；一般變更停止 500ms 後自動保存，建立、匯入、刪除、拖曳完成及頁面隱藏／關閉前立即嘗試保存。保存狀態與未匯出狀態分開呈現；保存失敗時保留記憶體內容，提供有限次重試與救援匯出，並阻止會覆蓋工作副本的建立、匯入與清除。
- **本機清除**：清除唯一工作副本是明確確認的危險操作；完成後建立全新文件與全新文件／根節點 ID。
- **原生格式**：.quickmind 是版本化 UTF-8 JSON；v1 只接受 schemaVersion 為 1，缺少、未知、未來或其他版本一律拒絕。Schema 嚴格拒絕未知欄位與歧義 JSON；匯入解析與驗證失敗時保持目前工作副本不變。格式包含階層、節點標題、ID、時間與 isCollapsed，不包含 Undo／Redo、視圖狀態、匯出狀態或瀏覽器工作區 metadata。
- **原生匯入**：有效且與目前內容不同的檔案以一筆完整文件取代處理；Undo 回到匯入前完整狀態，Redo 恢復匯入文件。完全相同的匯入是 no-op，不建立歷史、不更新時間、不改變匯出狀態。v1 不使用 File System Access API 靜默覆寫、檔案 handle 保存或 OS 雙擊開啟。
- **原生匯出**：使用者明確要求後透過瀏覽器標準下載產生 .quickmind；檔名由根節點標題安全清理，成功下載才清除未匯出狀態，失敗時保留內容與重試狀態。匯出是完整 round-trip 格式，不以匯出取代本機工作副本。
- **文件限制**：工作區、原生匯入與原生匯出共用 10 MB UTF-8 JSON byte size 與 10,000 節點上限。這是資料與檔案生命週期的拒絕邊界，不是 10,000 節點的效能承諾；第一階段正常使用仍為 50 個節點以下。超限操作原子拒絕，不套用、不進歷史、不更新時間、不保存。
- **離線**：第一次成功載入後，核心建立、編輯、保存、恢復、匯入與匯出可在原分頁離線完成；第一次尚未載入且離線時顯示需要連線的說明。離線提示不阻止核心操作，網路恢復不自動上傳文件，也不啟用遙測。
- **視覺與無障礙**：莫蘭迪是視覺方向，v1 提供一套具基本對比的預設主題；深色／淺色切換、主題持久化與 FOUC 防護列入後續 stage。核心操作需可由鍵盤完成，控制項使用原生語意元素，焦點可見，狀態不只靠顏色表達；不指定隱藏語意樹或完整 ARIA tree 同步作為 v1 架構。
- **第一階段規模與效能**：50 個節點以下以正確性、互動可用性與資料安全為主要驗收面向。不要求固定 60 FPS、O(1) 記憶體、數百節點自動折疊、DOM 剔除、Worker、虛擬化或 Minimap。
- **建置與發布**：本地與 GitHub Actions 共用 Docker Compose；Pull Request 執行 Docker 化的 typecheck、domain／unit tests、build 與 Chromium smoke test，並建立 Docker image；`main` 合併後只有在全部檢查通過時才將 `/QuickMind/` base path 的純靜態產物發布到 GitHub Project Pages。Docker 是本地與 CI 的執行邊界，不是使用者執行 QuickMind 的必要條件。
- **後續 stage 方向**：Stage 2 方向為文件搜尋、PWA 安裝與 Light／Dark 主題；Stage 3 方向為外部格式讀取與 PNG、PDF、Mermaid、draw.io 等輸出；Stage 4 方向為依實際需求進行大規模渲染與效能最佳化。後續格式保真、匯入／匯出操作語義與效能方案不在本規格凍結。

## Testing Decisions

- **測試原則**：測試外部可觀察行為、資料不變量與使用者可恢復性，不測試特定框架、套件、目錄結構或內部函式呼叫。測試應從最高層的文件工作流邊界驗證「命令進入後，文件、歷史、保存狀態與可見結果是否正確」。
- **主要測試 seam**：以單一文件工作流／文件狀態邊界作為最高測試 seam，集中驗證樹狀操作、歷史、原生格式與工作狀態；瀏覽器 smoke test 只負責補足真實鍵盤、滑鼠、離線與瀏覽器生命週期。
- **文件與樹狀工作流**：測試單一根節點、單一父節點、children 順序、同名節點、標題規則、拖曳防循環、根節點保護、刪除子樹、展開／收合與超限原子拒絕。
- **歷史工作流**：測試每個文件操作的單筆歷史、標題提交／取消、Undo／Redo、Redo 分支清除、匯入取代的一筆完整歷史，以及 Undo／Redo 後恢復完整文件狀態。
- **原生格式工作流**：測試有效 .quickmind 的 serialize／parse round-trip；測試 schemaVersion、未知欄位、重複 JSON key、錯誤 ID、錯誤時間、循環或不完整樹狀資料被拒絕時目前工作副本不變；測試相同匯入 no-op 與 10 MB／10,000 節點限制。
- **保存與離線工作流**：測試新文件立即保存、延遲保存、重要操作立即保存、啟動恢復、保存失敗保留記憶體內容、重試與救援匯出、首次成功載入後離線核心使用，以及首次未載入離線時的說明頁。
- **Chromium smoke flow**：至少有一條從使用者視角涵蓋建立根節點、建立子節點與同層節點、重新命名、拖曳、收合、Undo／Redo、保存、重新開啟、原生匯入／匯出與離線核心操作的流程；應驗證可見結果與文件恢復，而不是內部 store 或元件細節。
- **鍵盤與可用性**：測試核心操作可由鍵盤完成、文字輸入時原生 Undo／Redo 優先、CJK 組字不被攔截、焦點在新增／刪除／拖曳／選單後符合規格、停用控制項使用原生 disabled。
- **CI／發布**：測試 Pull Request 未通過 Docker Compose 檢查、Docker 建置或任何核心檢查時不允許發布；`main` 全部通過後可產生並發布純靜態產物到 GitHub Project Pages。部署檢查只驗證交付結果可建置與發布，不把 GitHub Pages 當成文件資料儲存層。
- **既有測試先例**：目前 repository 沒有實作程式或既有測試，因此沒有可沿用的測試先例；第一階段應先建立 domain／workflow tests、Chromium smoke test 與 CI gate。視覺回歸 threshold、完整跨瀏覽器矩陣、極端負載與複雜測試 fixture 不屬於本階段必要測試。

## Out of Scope

- 文件搜尋；Stage 2 只先保留方向，不在本規格定義搜尋介面與結果語義。
- PWA 安裝、manifest file handler、OS 雙擊開啟與檔案 handle 靜默覆寫。
- XMind／OPML 等外部格式讀取，以及 PNG、PDF、Mermaid、draw.io 等進階輸出；這些只列為後續 stage 方向。
- Light／Dark 主題切換、主題持久化、固定色票契約與首屏 FOUC 防護。
- 大規模文件效能承諾，包括固定 60 FPS、O(1) 記憶體、數百節點自動折疊、DOM 剔除、Worker、虛擬化與 Minimap。
- Markdown 備註、圖片附件、個別節點樣式、跨連結、分組外框、多父節點、自由定位、多選、批次操作與多文件工作區。
- 雲端同步、跨裝置同步、跨頁籤同步、登入、後端 API、團隊協作、伺服器備份、遙測與行動瀏覽器正式支援。
- 本地時光機、歷史快照側欄、Safe Mode 儀表板、PII 日誌系統與其他極端容錯架構。
- 視覺回歸 threshold、全瀏覽器相容性保證、極端大規模壓力測試與尚未驗證的效能架構。
