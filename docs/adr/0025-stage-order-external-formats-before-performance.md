# 先完成外部格式互通，再投入大規模效能最佳化

QuickMind 的後續 stage 只先確認方向與順序：Stage 2 預計處理文件搜尋、PWA 安裝與 Light／Dark 主題；Stage 3 預計處理外部格式讀取，以及 PNG、PDF、Mermaid、draw.io 等輸出方向；Stage 4 再依實際需求處理大規模文件的渲染與效能最佳化。格式細節、保真程度、匯入／匯出範圍與操作語義，等進入對應 stage 時再逐步定義；v1 的 `.quickmind` 原生匯入匯出仍屬核心能力，不受此排序影響。這個順序先確保產品方向與優先級一致，同時避免在需求尚未驗證前凍結後續 stage 的技術與驗收細節。
