# Undo／Redo 涵蓋所有文件操作

節點標題編輯期間，原生輸入框優先處理 Undo／Redo 與其他文字編輯快捷鍵，這些操作只作用於目前輸入文字，不觸發文件層級歷史；CJK 組字期間不攔截快捷鍵。

非編輯狀態下以 `Delete` 刪除目前選取的非根節點整棵子樹；沒有選取或選取根節點時不做任何事，根節點不受影響，不使用 `Backspace`，也不增加確認對話框，因為刪除本身可由單次 Undo 還原。

QuickMind v1 將所有會改變文件內容或結構的使用者動作納入同一套 Undo／Redo 歷史，包括新增、重新命名、刪除、拖曳移動與展開／收合，每個使用者動作形成一筆歷史；連續標題編輯只在 `Enter` 提交且內容實際改變時形成一筆，`Esc` 取消或提交相同內容則不留下歷史或文件時間變更。新節點若取消或提交空白標題就直接移除，也不形成歷史。有效匯入若內容不同，形成一筆整份文件取代歷史，不論文件 ID 是否相同，可由單次 Undo 還原並由 Redo 恢復；這類歷史保存取代前後的完整工作狀態，包括文件 ID、metadata 與未匯出狀態，且不帶入來源檔案的歷史。Undo／Redo 完成後立即保存恢復的工作狀態，但不新增歷史，也不改寫恢復狀態的 `updatedAt` 或匯出狀態。桌面快捷鍵使用 `Ctrl`／`⌘` + `Z` 執行 Undo、`Ctrl`／`⌘` + `Shift` + `Z` 執行 Redo，Windows／Linux 另支援 `Ctrl` + `Y`；文字編輯時由原生輸入框優先處理。畫面同時提供真正的 `<button>` Undo／Redo 控制項，具備可見名稱或 `aria-label` 與含快捷鍵的 tooltip，無法使用時使用原生 `disabled`；沒有可用歷史時停用但仍顯示快捷鍵提示，按鈕與快捷鍵共用相同流程。歷史最多保留最近 100 筆，超過後只丟棄最舊歷史，不改變文件內容。Undo 後若發生新的文件變更，清除整個 Redo 分支，Undo／Redo 本身不新增歷史。這讓使用者可以完整回復近期整理行為，同時以固定容量控制本機資源；代價是較早的操作不再可復原，且展開／收合也會消耗歷史容量。
