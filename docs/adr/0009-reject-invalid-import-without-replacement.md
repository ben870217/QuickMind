# 無效匯入不得取代目前工作副本

QuickMind v1 對 `.quickmind` 匯入採全有或全無的嚴格驗證邊界，入口包含檔案選擇器與將檔案拖放到應用程式視窗；只接受 `.quickmind` 副檔名。畫布拖放若包含檔案資料，優先走檔案匯入，沒有檔案資料才走節點拖曳。JSON 無法解析、出現重複 key、Schema 不符合、未知欄位、格式版本未知、檔案超過 10 MB、節點超過 10,000 個或階層樹違反規則時，整份匯入被拒絕，且目前本機工作副本保持不變；未知欄位不被忽略或靜默移除，重複 key 也不依 parser 預設選擇值，超量資料不被截斷或部分載入。若有效匯入內容與目前工作副本完全相同，則視為 no-op，不建立歷史、不更新 `updatedAt`、不改變未匯出狀態、不重新保存。其他有效匯入完成後，工作副本視為已匯出且沒有未匯出變更，因為其內容與剛驗證的原生檔案一致；後續使用者修改才重新產生未匯出變更。UI 以簡短的一般訊息說明失敗與原文件未變更，並提供可展開的詳細驗證原因。詳細資訊不得直接回顯節點標題、備註或其他文件內容，只顯示欄位路徑、索引、錯誤類型與必要的截斷值。這避免不完整或惡意資料以部分成功的方式污染使用者現有內容，也避免錯誤介面意外暴露使用者資料。
